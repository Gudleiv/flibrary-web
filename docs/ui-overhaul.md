## Что уже выяснено про данные

Разбиралось по коду FLibrary (`heimdallr/books`) и по фикстурам; переспрашивать не нужно.

- **Аннотации в коллекции опциональны.** `Annotations` заполняется при импорте inpx
  только с флагом `LoadAnnotations` (`src/home/inpx/inpx.h:35`, `inpx.cpp:1987`). Если
  коллекция собрана без него — таблица пуста, и тогда «аннотации нет» на каждой книге
  и пустая выдача при поиске по аннотации не баг нашего кода, а свойство коллекции.
  Десктопный FLibrary в этом случае берёт аннотацию не из БД, а разбирает fb2 на лету
  (`AnnotationController`, готовность `Ready::Archive`). На фикстурах таблица заполнена
  и всё работает — проверено, `POST /search` по `field: annotation` находит.
- **Счётчики корневых жанров нулевые по-настоящему.** Книге в `Genre_List` проставляют
  листовые жанры, а `/genres` считает только прямые связи. Нужен подсчёт по поддереву.
- **Дерево жанров API отдаёт правильно** (`001` → `001.001`, …). Плоским его делает
  клиент: `SearchView.vue` разворачивает дерево в список для `MultiSelect`, а отступы
  рисует пробелами, которые HTML схлопывает.
- **Издатель, язык оригинала, переводчики, размер в буквах, страницы, слова,
  содержание (главы)** — в коллекционной БД их нет вообще. Всё это FLibrary достаёт
  разбором fb2 (`AnnotationController.cpp:862` — «букв ≈ страниц, слов»). Значит,
  нужен файл книги, то есть живой content-service.
- **Отзывы** лежат вне БД: `Reviews (BookID, Folder)` — это указатель на архив
  `<additional>/reviews/<Folder>.7z`, внутри которого файл с именем
  `<FolderTitle>#<FileName><Ext>` и JSON-массивом `{name, time, text}`
  (`AuthorReviewModel.cpp:113`). Нужен и 7z, и путь к «дополнительной папке» коллекции.

## Фаза 1. Утилиты формата и мелочи

Ничего не ломает, нужна всем остальным фазам.

0. Убрать подпись «Регистрации нет — аккаунт создаёт администратор» из формы входа
   (`LoginView.vue:41`). Пользователю она объясняет отсутствующую кнопку, которой он
   и не искал. В `openapi.yaml` и `auth/users.ts` то же самое сказано разработчику —
   там оно к месту и остаётся.
1. `packages/web/src/lib/format.ts` — `formatSize(bytes)`: Б / КБ / МБ / ГБ, один знак
   после запятой начиная с МБ. Заменить ручной `/1024` в `BookRow.vue` и вывести размер
   в карточке книги (там его сейчас нет вовсе).
2. `packages/web/src/lib/lang.ts` — `languageName(code)` человекочитаемо. Основа —
   `Intl.DisplayNames(['ru'], { type: 'language' })`, поверх словарь для кодов, которых
   он не знает (`mul`, `und`, устаревшие трёхбуквенные). Фолбэк — сам код в верхнем
   регистре, не пустота.
3. `packages/web/src/components/FlagIcon.vue` — мини-флаг по коду языка.

   **Решение:** рисуем сами, инлайновым SVG, без зависимости и без emoji. Emoji-флаги
   отпадают: Windows их не рендерит (показывает «RU» буквами), а это ровно тот случай,
   когда «иконка» выглядит поломкой. Пакет вроде `flag-icons` — мегабайт ассетов ради
   двух десятков картинок. Большинство нужных флагов — две-три полосы, они задаются
   таблицей `{ code, dir: 'h' | 'v', colors: [...] }`; сложные (GB, US) — отдельными
   путями. Неизвестный язык — нейтральный глобус, а не пустое место.

   Язык — не страна, поэтому таблица именно «язык → флаг», и спорные случаи
   (`en` → 🇬🇧) фиксируются комментарием рядом.

## Фаза 2. API справочников

Контракт правим первым, потом `pnpm --filter @flibrary/contract build`.

1. **`GET /genres` — счётчики по поддереву.** Один рекурсивный CTE разворачивает
   `ParentCode` в пары «корень поддерева → потомок», дальше `count(DISTINCT gl.BookID)`.
   `DISTINCT` обязателен: книга с двумя поджанрами одного корня не должна считаться
   дважды. Справочник жанров маленький, разворот дешёвый.
   В контракте: `books` — по поддереву (то, что видит пользователь), новое `ownBooks` —
   прямые связи. Ломать смысл `books` нельзя молча, поэтому меняем его описание в
   `openapi.yaml` явно.
2. **`GET /authors`** — постраничный список для страницы «Авторы»:
   `?q=&limit=&offset=` → `{ items: [{ authorId, name, books }], total }`. Сортировка по
   имени. `q` — префикс по `SearchName` (uppercase, как и `SearchTitle`).
   Существующий `/search/suggest?kind=author` для этого не годится: он даёт топ-N
   подсказок, а не алфавитный список с листанием.
3. **`GET /collection`** — добавить `yearMin` / `yearMax` (для range-компонента года) и
   `annotations` — число записей в `Annotations`. Последнее нужно, чтобы UI мог честно
   сказать «в этой коллекции аннотаций нет», а не «у этой книги нет аннотации».

## Фаза 3. Страница поиска

`SearchView.vue` + `useSearchState.ts`.

1. Заголовок карточки фильтров — «Поиск» вместо «Фильтры».
2. **Раздельные поля «Название» и «Автор».** В форме вместо `text` + `field` —
   `title` и `author`; в дерево предикатов уходит `and` из двух `prefix`-узлов
   (пустое поле узла не даёт). Селект «где искать» и поле «Что ищем» убираются.
3. **Совместимость URL — обязательна.** Старые ссылки `?q=…&in=…` должны открываться:
   `fromQueryParams` продолжает читать `q`/`in` и раскладывает их по новым полям
   (`in=author` → `author`, всё прочее → `title`). Пишем в URL уже только новые ключи
   `title` / `author`. Тест на это — в фазе 8.
4. **Год — range.** `Slider` в режиме `range` плюс два числовых поля по краям: ползунок
   без цифр не даёт задать точный год. Границы — из `yearMin` / `yearMax` коллекции.
5. **Язык — человекочитаемо + флаг.** `MultiSelect` с `option-label` из `languageName`
   и `FlagIcon` в слотах `option` и `chip`. Сортировка А-Я по названию, а не по числу
   книг, как сейчас.
6. **Жанры — дерево.** `TreeSelect` (`selection-mode="checkbox"`) вместо `MultiSelect`
   по плоскому списку. Счётчик в подписи — из фазы 2. Выбор родителя по-прежнему
   означает «с потомками» (`includeChildren: true` в предикате уже есть).
7. Панель «Уточнить» показывает язык так же человекочитаемо — сейчас там сырой код.

## Фаза 4. Страницы навигации

Новые разделы в `Menubar`: Поиск · Авторы · Жанры · Языки.

Общая раскладка одна — боковое меню слева, книги справа; выносится в
`components/BrowseLayout.vue`, список книг с пагинацией — в `components/BookList.vue`
(его же начинает использовать `SearchView`, чтобы разметка выдачи не разъехалась).

- `/authors` и `/authors/:authorId` — список авторов с поиском по началу имени и
  листанием (`GET /authors`).
- `/genres` и `/genres/:code` — `Accordion`/`Tree` по дереву жанров.
- `/languages` и `/languages/:code` — языки, человекочитаемо, с флагом, **сортировка
  А-Я по названию**.

Выбранный элемент — часть пути, а не состояние компонента: тогда «назад», «вперёд»,
перезагрузка и поделиться ссылкой работают сами. Выдача — тот же `POST /search` с
предикатом `authorId` / `genre` / `lang`; отдельных ручек выдачи не заводим.

## Фаза 5. Карточка книги: метаданные из коллекции

Всё, что уже лежит в БД. Ничего не ждёт content-service.

1. **Метаданные — определениями, а не свалкой тегов.** Сейчас серия, год, язык, жанры и
   рейтинг свалены в одну строку `Tag`-ов и неразличимы. Делаем `dl`-таблицу
   «подпись — значение»: Автор, Серия (с номером), Жанр, Год, Язык, Формат, Размер,
   Дата обновления, Источник, Архив, Файл, Рейтинг, Ключевые слова.
2. **Кликабельность.** Автор → `/search?author=…` (по `authorId`), Серия → по `seriesId`,
   Жанр → по коду, Год → диапазон из одного года, Язык → по коду, Формат → по `ext`.
   Обычные `RouterLink`, чтобы работали средняя кнопка и «открыть в новой вкладке».
3. **API добавляет недостающее:** `SourceLib` (Источник) и `LibID` в `SELECT` карточки —
   в контракте их сейчас нет. `updateDate` уже приходит, но не показывается.
4. **Размер** — через `formatSize` из фазы 1.
5. **Честный текст про аннотацию.** Если `annotations === 0` по коллекции — пишем
   «коллекция импортирована без аннотаций», а не «у книги нет аннотации». Это разные
   вещи, и вторая вводит в заблуждение (см. «Что уже выяснено»).

## Фаза 6. Карточка книги: данные из файла книги

Здесь появляется всё, чего в БД нет: аннотация-фолбэк, содержание, издатель, язык
оригинала, переводчики, буквы/страницы/слова.

Новая ручка `GET /books/{bookId}/details`: тянет fb2 через content-service
(`/Images/fb2/{id}`, дорожка `file`), разбирает `<description>` и текст, кладёт разбор
в дисковый кэш рядом с обложками. Разбор fb2 — наш (это XML, а не архив), но **файл
достаём только через content-service**: распаковку архивов не переписываем (инвариант 5).

Отдаёт: `annotation`, `publisher`, `srcLang`, `translators[]`, `chapters[]`,
`letters`, `words`, `pages` (буквы / 2000 — та же формула, что в FLibrary,
`AnnotationController.cpp:862`).

Клиент грузит это отдельным запросом и **не блокирует им карточку**: без
content-service ручка отдаёт 502, и это штатно (в облачной сессии — всегда). В UI —
свёрнутый блок «Содержание» и дополнительные строки метаданных, появляющиеся по
готовности. Аннотация из файла используется, только если в БД её нет.

Проверяемость: в облачной сессии живьём не проверить, поэтому разбор fb2 закрывается
юнит-тестами на фикстурных fb2 (`fixtures/src/fb2.ts` их уже умеет генерировать),
а поход в content-service — моком.

## Фаза 7. Отзывы читателей

Самостоятельный кусок, и он последний осознанно: у него другая цена: нужен 7z-ридер в
Node и путь к «дополнительной папке» коллекции, которого в конфиге сейчас нет.

1. `REVIEWS_DIR` в конфиге (пусто = фичи нет, никаких ошибок).
2. `GET /books/{bookId}/reviews` → `[{ name, time, text }]`, отсортировано по времени.
   Читаем `Reviews.Folder`, открываем `<REVIEWS_DIR>/<Folder>.7z`, достаём запись
   `<FolderTitle>#<FileName><Ext>`, парсим JSON. `<br/>` в тексте → перевод строки.
3. В карточке — блок «Отзывы»: ник · дата · текст.

Если 7z в Node окажется неоправданно дорогим — фаза выносится из этого PR отдельной
задачей, а не делается наполовину. Решение принимается в начале фазы, не раньше.

## Как вести работу

Контейнер сессии временный: незапушенное пропадает вместе с ним.

- **Ветка одна на всё** — `claude/flibrary-web-ui-updates-x40xjk`, в обоих репозиториях.
  Один PR в конце.
- **Коммит и пуш в конце каждой фазы**, не реже. Перед этим — `pnpm typecheck && pnpm lint`.
  Сообщение коммита — по существу фазы, без номера («Жанры: счётчики по поддереву», а не
  «Фаза 2»).
- **Таблицу статуса выше обновлять тем же коммитом.** Она — единственное, что переживает
  сжатие контекста.
- **Сжимать контекст (`/compact`) между фазами**, сразу после пуша, а не в середине.
  В середине фазы теряется то, что ещё не записано ни в код, ни в этот файл.
- **Возобновление после сжатия или в новой сессии:** «Читай `docs/ui-overhaul.md`,
  продолжай с первой неотмеченной фазы». Больше вводных не нужно — всё выясненное про
  данные записано выше, заново разбирать код FLibrary не придётся.
- **Окружение** поднимает SessionStart-хук (зависимости, контракт, 5 000 книг фикстур,
  индекс, пользователь `dev` / `dev`). Обложки и скачивание отдают 502 — content-service
  в облачной сессии нет, это ожидаемо и в фазе 6 учтено.
